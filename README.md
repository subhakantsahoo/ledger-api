# Transaction Ledger API

A small backend for keeping account balances using credit and debit transactions.
Built with **Node.js, Express 5, MongoDB and Mongoose**.

**Live API:** https://ledger-api-244a.onrender.com
(health check: [/health](https://ledger-api-244a.onrender.com/health), all routes are under `/api`, see [API documentation](#api-documentation))

- Create accounts, add credits/debits, check balance, see transaction history
- Bonus: transfer money between two accounts (all or nothing)
- Safe under parallel requests: no overdrawn balances, no duplicate transactions
- Transactions can never be edited or deleted

## Project structure

```
src/
  server.js             connects to MongoDB, then starts the server
  app.js                express app, routes, error handler
  db.js                 connectDB(), collection rules, withTransaction() helper
  keepAlive.js          pings /health every 14 min while running on Render
  models/
    Account.js
    Transaction.js      unique index + hooks that block update/delete
  routes/index.js       all the routes in one place
  controllers/          read the request, call the service, send the response
  services/             business logic and database calls
  middleware/errorHandler.js
  utils/validators.js   input checks
  utils/money.js        rupees <-> paise
  utils/AppError.js
tests/                  jest + supertest, runs against the ledger_test database
docker-compose.yml      local MongoDB (single node replica set)
```

Flow of a request: `route -> controller (validate input) -> service (database calls inside a MongoDB transaction) -> response`.
Any error thrown along the way ends up in `errorHandler.js`, so every error has the same JSON shape.

## Running locally

You need **Node.js 18+** and **Docker** (for MongoDB).

> MongoDB transactions only work on a **replica set**, not on a plain standalone `mongod`.
> The docker-compose file starts a replica set with one member, so you don't have to set anything up.
> MongoDB Atlas is always a replica set, so it works there too.

```bash
# 1. install packages
npm install

# 2. create your env file
cp .env.example .env

# 3. start MongoDB (waits until the replica set is ready)
docker compose up -d --wait

# 4. start the API
npm run dev        # restarts on file changes
# or
npm start
```

The API runs at `http://localhost:3000`. Check it with `GET /health`.
Collections, validation rules and indexes are created automatically when the server starts.

Docker MongoDB uses port **27020** so it doesn't clash with a MongoDB already installed on 27017.

### Environment variables

| Name | What it's for | Example |
|---|---|---|
| `PORT` | port for the server | `3000` |
| `MONGODB_URI` | MongoDB connection string | `mongodb://localhost:27020/ledger?directConnection=true` |

### Running tests

```bash
npm test
```

The tests use the separate `ledger_test` database and clear it before each test, so your dev data is safe.
They cover validation, error codes, pagination, and the concurrency cases (parallel debits,
parallel duplicate requests, opposite transfers at the same time).

## API documentation

Base URL: `http://localhost:3000/api`. All requests and responses are JSON.
Account ids are MongoDB ObjectIds (24 hex characters).

### Error format

Every error looks like this:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid request data",
    "details": [{ "field": "amount", "message": "amount must be a number greater than 0 with at most 2 decimal places" }]
  }
}
```

| Status | Code | When |
|---|---|---|
| 400 | `VALIDATION_ERROR` | a field is missing or wrong (details lists every bad field) |
| 400 | `INVALID_ACCOUNT_ID` | account id in the URL is not a valid id |
| 400 | `INVALID_JSON` / `INVALID_BODY` | body is not valid JSON / not a JSON object |
| 404 | `ACCOUNT_NOT_FOUND` | account doesn't exist |
| 404 | `ROUTE_NOT_FOUND` | unknown URL or method |
| 409 | `DUPLICATE_TRANSACTION` | reference_id already used on this account |
| 422 | `INSUFFICIENT_BALANCE` | debit or transfer is more than the balance |
| 500 | `INTERNAL_ERROR` | anything unexpected (logged on the server) |

### 1. Create account

`POST /api/accounts`

```json
{ "name": "Asha Verma" }
```

Response `201`

```json
{
  "id": "6ae0d348ebb8f66fe078aa7f",
  "name": "Asha Verma",
  "balance": 0,
  "created_at": "2026-10-27T16:37:28.779Z"
}
```

- `name` is required, max 100 characters (spaces around it are trimmed)
- `balance` can't be sent, sending it gives a 400. Every account starts at 0
- `id` and `created_at` are generated by the server

There's also `GET /api/accounts/:id` which returns the same object.

---

### 2. Add transaction

`POST /api/accounts/:id/transactions`

```json
{
  "type": "credit",
  "amount": 1000.10,
  "reference_id": "INV-1001",
  "description": "Salary for October"
}
```

| Field | Rules |
|---|---|
| `type` | `credit` or `debit` |
| `amount` | JSON number, > 0, max 2 decimal places, max 1,000,000,000 |
| `reference_id` | required, max 100 characters, unique per account |
| `description` | optional, max 255 characters |

Response `201`

```json
{
  "transaction": {
    "id": "6ae0d348ebb8f66fe078aa85",
    "account_id": "6ae0d348ebb8f66fe078aa7f",
    "type": "credit",
    "amount": 1000.1,
    "description": "Salary for October",
    "reference_id": "INV-1001",
    "created_at": "2026-10-27T16:37:28.880Z"
  },
  "balance": 1000.1
}
```

Duplicate `reference_id` on the same account, response `409` (nothing is saved, balance unchanged):

```json
{
  "error": {
    "code": "DUPLICATE_TRANSACTION",
    "message": "A transaction with this reference_id already exists for this account",
    "details": { "existing_transaction": { "id": "6ae0d348ebb8f66fe078aa85", "amount": 1000.1, "...": "..." } }
  }
}
```

Debit more than the balance, response `422`:

```json
{
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "Not enough balance for this debit",
    "details": { "account_id": "6ae0d348ebb8f66fe078aa7f", "balance": 1000.1, "requested": 5000 }
  }
}
```

### 4. Transaction history

`GET /api/accounts/:id/transactions?type=debit&page=1&limit=10`

| Query | Default | Rules |
|---|---|---|
| `type` | all | `credit` or `debit` |
| `page` | 1 | whole number, 1 or more |
| `limit` | 10 | whole number, 1 to 100 |

Newest transactions come first.

Response `200`

```json

  "data": [
    {
      "id": "6ae0d348ebb8f66fe078aa85",

      "amount": 1000.1,
      "description": "Salary for October",
      "reference_id": "INV-1001",
      "created_at": "2026-10-27T16:37:28.880Z"
    }
  ],
  "pagination": { "page": 1, "page_size": 10, "total_records": 1, "total_pages": 1 }
}
```

### 5. Transfer (bonus)

`POST /api/transfers`

```json
{
  "from_account_id": "6ae0d348ebb8f66fe078aa7f",
  "to_account_id": "6ae0d348ebb8f66fe078aa81",
  "amount": 250,
  "reference_id": "TRF-001",
  "description": "Rent share"
}
```

Response `201`

```json
{
  "reference_id": "TRF-001",
  "amount": 250,
  "from_account": { "account_id": "6ae0d348ebb8f66fe078aa7f", "balance": 750.1 },
  "to_account": { "account_id": "6ae0d348ebb8f66fe078aa81", "balance": 250 },
  "transactions": [
    { "type": "debit", "account_id": "6ae0d348ebb8f66fe078aa7f", "amount": 250, "reference_id": "TRF-001", "...": "..." },
    { "type": "credit", "account_id": "6ae0d348ebb8f66fe078aa81", "amount": 250, "reference_id": "TRF-001", "...": "..." }
  ]
}
```

Errors: `400` same account or bad input, `404` either account missing, `409` reference already used,
`422` not enough balance. On any error nothing changes on either account.

## How data stays correct

**Balance + transaction saved together.** Every write runs inside `withTransaction()` in `src/db.js`,
which uses a MongoDB multi-document transaction. The balance update and the new transaction
either both get saved or neither does.

**Parallel debits.** The debit is one conditional update:

```js
Account.findOneAndUpdate(
  { _id: accountId, balance: { $gte: amount } },   // only if there's enough money
  { $inc: { balance: -amount } }
)
```

MongoDB checks the condition and changes the balance in a single atomic step on that document,
so two debits can't both pass on the same old balance. If nothing matched, we look up the account
to return either 404 (doesn't exist) or 422 (not enough balance). There's a test that fires 10 debits at once.

**Write conflicts.** If two transactions change the same account at the same moment, MongoDB aborts
one of them with a write conflict, and Mongoose's `connection.transaction()` runs it again automatically.
MongoDB doesn't make transactions wait on each other's locks, so there are no deadlocks,
even with A→B and B→A transfers at the same time (also tested).

**Duplicates.** Inside the transaction we look for the `reference_id` on that account and return 409 if it exists.
The unique index on `{ account_id, reference_id }` is a second safety net, if two requests race,
MongoDB refuses the second insert and the error handler still returns 409.

**Database rules**, so bad data can't get in even if someone skips the API (`src/db.js`):
- `$jsonSchema` validators on both collections: `balance >= 0`, `amount >= 1` (paise),
  `type` must be `credit` or `debit`, required fields. MongoDB checks these on every insert **and** update.
- unique index on `{ account_id, reference_id }`
- Mongoose hooks on the Transaction model throw on any update, replace or delete

**Money.** Amounts are stored in **paise** as whole numbers (`100.50` → `10050`) and converted
back in API responses (`utils/money.js`). Adding whole numbers is always exact, while decimals in JavaScript
are not (`0.1 + 0.2 = 0.30000000000000004`).

## Assumptions

- No login/auth, it wasn't part of the brief.
- The balance is stored on the account so reads are fast. It's only ever changed in the same
  MongoDB transaction as a new transaction document, so it always equals the sum of the transactions
  (a test checks this with an aggregation).
- Amount must be sent as a JSON number (`100` or `99.50`), not a string. Max 2 decimal places.
- A duplicate `reference_id` returns `409` with the existing transaction, even if the amount is different.
  The duplicate check runs before the balance check, so a retried debit gets "already exists".
- `reference_id` is case sensitive and trimmed.
- A transfer creates two normal transactions (debit on the sender, credit on the receiver) with the
  same `reference_id`. The reference must not be used on either account already.
- Asking for a page past the last one returns an empty `data` list (not an error).
- Times are stored and returned in UTC.
- "Not editable or deletable" is enforced in the API (no such routes), in the Mongoose model (hooks),
  and can be enforced for the database user too by giving it only `find` and `insert` rights on `transactions`.
- The brief jumps from section 5 to section 7. I assumed section 6 was a numbering mistake.

## Deployment

The app reads everything from env variables, so it can run anywhere Node or Docker runs.
The setup I used: **MongoDB Atlas** for the database and **Render** for the API.

1. **Database (MongoDB Atlas)**: create a free M0 cluster, add a database user, and under
   *Network Access* allow `0.0.0.0/0` (Render's free plan has no fixed IP).
   Copy the connection string and add the database name, e.g.
   `mongodb+srv://<user>:<password>@cluster0.xxxxx.mongodb.net/ledger?retryWrites=true&w=majority`
2. **API (Render)**: push this repo to GitHub, then in Render choose *New → Blueprint* and pick the repo.
   `render.yaml` sets up the service. Set `MONGODB_URI` to the Atlas URL when asked.
3. Open `https://<your-app>.onrender.com/health`. It should return `{"status":"ok"}`.

### Keeping the free server awake

Render's free plan puts the server to sleep after 15 minutes with no requests,
and the next request then takes ~30-60 seconds. Two things stop that:

1. **Self ping (`src/keepAlive.js`).** When the app runs on Render (Render sets `RENDER_EXTERNAL_URL`
   automatically), it calls its own `/health` every 14 minutes. Locally it does nothing.
2. **GitHub Actions cron (`.github/workflows/keep-alive.yml`).** A backup that calls `/health`
   every 14 minutes from GitHub. If the server ever does fall asleep (e.g. after a restart),
   this wakes it up again. It can also be run by hand from the *Actions* tab.

GitHub doesn't always run scheduled jobs exactly on time, which is why the self ping is the main one.
Running all month uses ~720-744 of the 750 free instance hours Render gives per month, so keep only
one free service running on the account.

**Docker / AWS.** There's a `Dockerfile` as well:

```bash
docker build -t ledger-api .
docker run -p 3000:3000 -e MONGODB_URI="<atlas url>" ledger-api
```

The same image can go to AWS App Runner or ECS, with the database on MongoDB Atlas.
